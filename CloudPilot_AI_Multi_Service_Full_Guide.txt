CLOUDPILOT AI — EC2 DEPLOYMENT

Deploy the existing CloudPilot AI app to an EC2 instance from either GitHub or your local project, then run it.

1. EC2 REQUIREMENTS
- Use an Amazon Linux 2023 EC2 instance.
- Allow SSH (TCP 22) only from your IP address.
- Attach an EC2 IAM role with the AWS and Amazon Bedrock permissions the app needs. Enable access to the Bedrock model used below.
- Do not open port 8000 to the internet. The app will be reached through an SSH tunnel.

2. PUT THE APP ON EC2
Choose ONE option.

Option A — Clone from GitHub (SSH into EC2, then run):

    sudo dnf update -y
    sudo dnf install -y git python3.11 python3.11-pip
    git clone https://github.com/devkunaljadhav/cloudpilot-ai-aws-services.git
    cd ~/cloudpilot-ai-aws-services/cloudpilot-ai

Option B — Copy your local project (run in Windows PowerShell from the repository root):

    ssh -i "C:\path\to\your-key.pem" ec2-user@EC2_PUBLIC_IP "mkdir -p /home/ec2-user/cloudpilot-ai"
    scp -i "C:\path\to\your-key.pem" -r .\cloudpilot-ai\app .\cloudpilot-ai\static ec2-user@EC2_PUBLIC_IP:/home/ec2-user/cloudpilot-ai/
    ssh -i "C:\path\to\your-key.pem" ec2-user@EC2_PUBLIC_IP
    sudo dnf update -y
    sudo dnf install -y python3.11 python3.11-pip
    cd ~/cloudpilot-ai

Leave the EC2 SSH session open and continue with step 3.

3. INSTALL AND RUN
Run on EC2 from the app directory:

    python3.11 -m venv .venv
    source .venv/bin/activate
    python -m pip install --upgrade pip
    pip install fastapi "uvicorn[standard]" boto3 pydantic
    export AWS_REGION=ap-south-1
    export BEDROCK_MODEL_ID=global.amazon.nova-2-lite-v1:0
    uvicorn app.web:app --host 127.0.0.1 --port 8000

Leave this terminal running.

4. OPEN THE APP FROM YOUR COMPUTER
Open a second Windows PowerShell window and start the SSH tunnel:

    ssh -i "C:\path\to\your-key.pem" -L 8000:127.0.0.1:8000 ec2-user@EC2_PUBLIC_IP

Open http://127.0.0.1:8000 in your browser. To check that the app is running, open http://127.0.0.1:8000/health.

Use SSH tunnel from your laptop/MobaXterm local port 8000 -> remote 127.0.0.1:8000. Browse http://127.0.0.1:8000. Do not add public inbound 8000.

7. TEST
- GET /health
- Ask: list my EC2, VPCs, subnets, SGs, S3, RDS, Lambda, CloudWatch alarms, IAM roles.
- Ask to create test VPC with an unused CIDR; review preview, confirm only if you accept it.
- Create subnet only with a valid VPC, non-overlapping CIDR, AZ in Mumbai.
- Create private S3 bucket using globally unique name; public access block is enabled.
- Create SG: created without inbound access.
- EC2 launch: use valid Mumbai AMI, subnet, SG, key pair. No public IPv4. Instance type restricted to small set.
- Confirm one operation at a time. Check AWS Console and billing.

8. KNOWN LIMITATIONS / HONEST STATUS
This guide provides a code starter, not a claim that it has been executed successfully in your account. Bedrock Converse tool-use compatibility depends on model/profile and SDK versions. Run tests in your account, read server logs, and fix validation/IAM errors without bypassing approval. No auth, persistence, multi-user protection, CSRF defense, durable audit, idempotency, or automated cost estimation. Do not deploy publicly until hardened.

9. COST & CLEANUP
EC2, EBS, S3, RDS, VPC networking, Bedrock calls and other AWS resources can bill. RDS and NAT Gateway can be costly. Use AWS Budgets and free-tier eligibility checks; free tier does not mean every resource/action is free. This starter does not delete resources automatically. Inspect dependencies and delete only known test resources in AWS Console.
